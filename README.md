# Proxy Manager

Windows-приложение, которое пускает выбранные программы через прокси (SOCKS5 / HTTP).
Остальные программы работают напрямую.

## Как это работает

Под капотом — ядро [sing-box](https://github.com/SagerNet/sing-box) в режиме TUN:

1. sing-box создаёт виртуальный сетевой адаптер `ProxyManager` и заворачивает в него весь трафик.
2. Для каждого соединения определяется процесс.
3. TCP программ из списка уходит в назначенный им прокси, их UDP блокируется
   (простые прокси не умеют UDP, а пропускать его напрямую — значит светить реальный IP через QUIC/WebRTC).
4. Всё остальное идёт напрямую.

Конфиг sing-box зависит только от списка прокси. Программы для каждого прокси лежат в отдельном
файле rule-set (`%AppData%\ProxyManager\apps-<id>.json`), который sing-box перечитывает на лету,
поэтому правила применяются без перезапуска ядра:

- **Дочерние процессы** — `ProcessRouter` следит за запуском процессов (WMI) и добавляет в rule-set
  по пути всех потомков программы из правила (например, `claude.exe`, который запускает VS Code),
  пока они работают.
- **Уже открытые соединения** — после изменения правил приложение через локальный API sing-box
  (Clash API на случайном порту с секретом) закрывает соединения, идущие не тем маршрутом, а соединения,
  открытые до включения прокси, сбрасывает через `SetTcpEntry`. Программы переподключаются уже правильно.

Ядро запускается как дочерний процесс (в job object — оно не переживёт падение приложения).

## Сборка

Нужен .NET 9 SDK.

```powershell
.\scripts\fetch-singbox.ps1          # скачать ядро sing-box в src\ProxyManager\core
dotnet build
dotnet test                          # PM_TEST_PROXY=socks5://user:pass@host:port — живая проверка прокси
```

Приложение требует прав администратора (TUN-адаптер и маршруты): при запуске без них оно
перезапускает себя через UAC.

## Выпуск версии

```powershell
.\scripts\build-release.ps1 -Version 0.2.0
```

Скрипт скачивает ядро (если нужно), прогоняет тесты, публикует self-contained single-file exe
(пользователю не нужен установленный .NET) и кладёт в `dist/`:

- `ProxyManager-<версия>-setup.exe` — установщик (Inno Setup: `winget install JRSoftware.InnoSetup`);
- `ProxyManager-<версия>-win-x64-portable.zip` — портативная версия.

Установщик ставит программу в Program Files, при обновлении закрывает запущенную копию,
при удалении убирает задачи автозапуска и по желанию — настройки.

Перед публичным выпуском:

- **Издатель** — `AppPublisher` в [installer/ProxyManager.iss](installer/ProxyManager.iss) и `<Company>`
  в [ProxyManager.csproj](src/ProxyManager/ProxyManager.csproj).
- **Подпись кода** — без неё Windows SmartScreen показывает «Неизвестный издатель», а антивирусы
  чаще ругаются (программа меняет сетевые маршруты). Место для `signtool` отмечено в `build-release.ps1`;
  подписывать нужно и `ProxyManager.exe`, и итоговый `setup.exe` (`SignTool` в Inno Setup).
- **Обновление sing-box** — `fetch-singbox.ps1 -Version X -Sha256 Y -Force`, SHA-256 архива берётся
  со страницы релиза на GitHub.

## Где что лежит

| Путь | Что |
|---|---|
| `src/ProxyManager/Services/SingBoxConfigBuilder.cs` | генерация конфига sing-box из правил |
| `src/ProxyManager/Services/SingBoxService.cs` | запуск/остановка ядра, журнал |
| `src/ProxyManager/Services/ProcessRouter.cs` | rule-set файлы, отслеживание дочерних процессов |
| `src/ProxyManager/Services/ClashApiClient.cs`, `TcpConnections.cs` | переподключение уже открытых соединений |
| `src/ProxyManager/Services/ProxyParser.cs` | разбор строк прокси при импорте |
| `src/ProxyManager/Services/ProxyTester.cs` | проверка прокси (внешний IP + задержка) |
| `src/ProxyManager/ViewModels/MainViewModel.cs` | логика интерфейса |
| `src/ProxyManager/Services/Autostart.cs` | автозапуск через Планировщик задач (с правами администратора, без UAC) |
| `installer/ProxyManager.iss` | установщик |
| `%AppData%\ProxyManager\settings.json` | настройки; пароли зашифрованы DPAPI |
| `%AppData%\ProxyManager\logs\crash.log` | журнал необработанных ошибок |

## Известные ограничения

- DNS-запросы в Windows делает системная служба, а не сама программа, поэтому имена сайтов
  резолвятся через обычный DNS (сам трафик при этом идёт через прокси).
- Правило матчит по имени `.exe`: одноимённые программы из разных папок попадут под одно правило.
- Дочерний процесс матчится по пути, поэтому пока он работает, через прокси идут и другие копии
  того же exe (например, `powershell.exe` из терминала VS Code — значит, и остальные PowerShell).
- Дочерний процесс попадает в список через доли секунды после старта: его самые первые соединения
  могут успеть уйти напрямую (потом они закрываются и переоткрываются через прокси).
- Изменение параметров самих прокси (адрес, логин, пароль) требует перезапуска ядра —
  кнопка «Применить изменения».
